# BlackBreak — Android Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A sideloaded Android app that covers the whole screen, status and navigation bars included, for 30 s every 20 min and swallows touches and keys. A phone call always holds a due break, and the dialer is never covered.

**Architecture:** `:core` is a pure Kotlin/JVM module: the port of `scheduler.js`, proven by `spec/scenarios.json` and `spec/traces.json`. `:app` has no AndroidX and uses the platform Material theme. Its `BreakService` (an AccessibilityService) owns the scheduler, the 1 s tick, the overlays and the key filter. `MainActivity` is the only screen: status, pause, calls and setup.

**Tech Stack:** Kotlin 2.x, AGP 8.x, Gradle wrapper, JDK 17 (`/usr/lib/jvm/java-17-openjdk-amd64`), minSdk 26, target/compileSdk 36, JUnit 5 (core), AndroidX Test only in `androidTest`.

**Spec:** `docs/superpowers/specs/2026-10-23-blackbreak-design.md` (Platforms → Android). Also `2026-10-23-shared-traces-release.md`.

## Global Constraints

- All timing values, the four break lines, the colours, `Break in 10 s`, the 35 s fail-safe, pause and call rules: as in `2026-10-23-linux-gnome.md` Global Constraints, verbatim.
- **Spec amendment (owner decides at plan review):** no foreground service. The AccessibilityService is bound and kept alive by the system, so it owns the timer, and there is no permanent notification. For the same reason there is no battery-optimisation step in the setup.
- **Spec amendment:** idle is measured by `ACTION_SCREEN_OFF`/`ON`. While the screen is off there is no tick. On screen-on, `update(now, idleMs = offDuration)` and then `update(now, 0)`, so 5 min or more off counts as rest. This matches the spec ("Idle = screen off for 5 minutes").
- Calls without any permission, from `AudioManager.mode`:
  - `MODE_RINGTONE` or `MODE_IN_CALL` → `inPhoneCall` (always counts);
  - `MODE_IN_COMMUNICATION` → `inCall`, but only when the exemption is on and `Microphone in use` is on.
  - A camera-only rule is not on Android in v1 (VoIP apps use the communication mode). The screen shows only the main switch.
- **The dialer is never covered:** if `inPhoneCall` becomes true during a break, the break overlay is removed at once and the break counts as done.
- Package `io.github.junkers4.blackbreak`. App name `BlackBreak`. Theme `@android:style/Theme.DeviceDefault.DayNight`. No AndroidX in `:app` main.
- Persistent data (`SharedPreferences` `blackbreak`): `lastPauseDay`, `callExemption`.
- Screen copy:
  - status `Next break at HH:MM` / `Paused until HH:MM` / `BlackBreak is off`;
  - buttons `Pause 30 min`, `Pause 1 hour`, `Pause 2 hours`, `Pause 3 hours`, `Cancel pause`;
  - switch `Wait with the break while I'm in a call`, caption `A break waits at most 3 hours. Phone calls always wait.`;
  - setup `Turn on BlackBreak in Accessibility settings` (opens `Settings.ACTION_ACCESSIBILITY_SETTINGS`), shown only while the service is off.
- Debug: a debug build with `adb shell setprop debug.blackbreak.fast 1` → scale 60.
- APK size target: under 1 MB.

## Review Focus

- **Gesture navigation (swipe home or back) during a break** → still black, nothing usable underneath. The `TYPE_ACCESSIBILITY_OVERLAY` stays above the launcher. Task 3 has an instrumented test, `home during break keeps overlay`, plus a manual item.
- **Incoming call during a break** → the overlay disappears at once and the call screen is usable. Task 3 has a unit test on `BreakController` and a manual item.
- **The accessibility service is killed or disabled during a break** → no stuck overlay. Overlays are attached to the service's window manager and die with it. The independent 35 s fail-safe `Handler` is armed first. Task 3.
- **Reboot, or the app updated over adb during a pause** → the service rebinds and starts a fresh interval. `lastPauseDay` survives, so no second pause that day. Task 2 traces, plus a manual item.
- **Rotation or fold or display-size change during a break** → still covers everything. `MATCH_PARENT` plus `LAYOUT_IN_DISPLAY_CUTOUT_MODE_ALWAYS`, with no fixed sizes. Manual item.

### Task 2: Break controller (pure)

**Interfaces — produces:**
- `data class Show(val notice: Boolean, val breakEndsAt: Long?)`.
- `class BreakController(private val scheduler: Scheduler)` has `fun tick(now: Long, idleMs: Long, audioMode: Int, exemption: Boolean): Show`:
  - it maps the audio mode to `inCall`/`inPhoneCall` by the Global Constraints rule;
  - `inCall` is only passed in the call-watch window (from 60 s before the warning is due, and while held);
  - it returns `breakEndsAt = null` while `inPhoneCall`, even in BREAK.
- `fun screenOn(now: Long, offMs: Long)` runs the two updates from the idle amendment.

  - `VoIP mode ignored when exemption off`;
  - `VoIP mode holds when on and seen before due`;
  - `phone call holds without exemption`;

### Task 3: Accessibility service and overlays

**Interfaces — consumes:** `BreakController`. **Produces:** `BreakService : AccessibilityService`, with `companion object { @Volatile var instance: BreakService? }` for the activity, and its methods `pause(minutes)`, `cancelPause()`, `state(): Scheduler`.

- `break_service.xml`:
  - `accessibilityFlags="flagRequestFilterKeyEvents"`, `canRequestFilterKeyEvents="true"`, `accessibilityEventTypes=""`;
  - description string: `Covers the screen for 30 seconds every 20 minutes. It reads no screen content.`
- Overlays use `TYPE_ACCESSIBILITY_OVERLAY` with these settings:
  - break: `MATCH_PARENT`, `FLAG_LAYOUT_IN_SCREEN | FLAG_LAYOUT_NO_LIMITS | FLAG_KEEP_SCREEN_ON`, cutout `ALWAYS`, `fitInsetsTypes = 0`, black background, touchable, consumes every touch;
  - break text: the four lines in `sans-serif-light`, `#9A9A9A`, plus the countdown `#5A5A5A`;
  - notice: `WRAP_CONTENT`, top-centre, `FLAG_NOT_TOUCHABLE | FLAG_NOT_FOCUSABLE`.
- `onKeyEvent` returns true while the break overlay is shown. Power is never delivered to it.
- The break has its own `Handler` fail-safe at `breakStart + 35 s`, armed before `addView`, and a hide at `breakEndsAt`.
- The tick is a `Handler` every 1 s. It stops on `SCREEN_OFF` and resumes with `screenOn` on `SCREEN_ON`. `onInterrupt` does nothing. `onDestroy`/`onUnbind` remove all views.

- [ ] **Step 1: Manual checklist** `android/test/manual-checklist.md`:
  - break covers status and nav bars;
  - taps, Back, Home and Recents gestures and volume keys do nothing useful;
  - incoming call removes the break;
  - a WhatsApp/Meet call holds when the switch is on and does not hold when it is off;
  - screen off 5 min is rest;
  - reboot gives a fresh interval and keeps the day's pause;
  - rotate during a break;
  - disabling the service in Settings is impossible during a break, and works outside it.
- [ ] **Step 2: Instrumented tests** (`androidTest`, emulator API 34). They enable the service with `UiAutomation.executeShellCommand("settings put secure enabled_accessibility_services …/.BreakService")` and the fast prop.
  - `break overlay covers and swallows taps`: a test activity button is not clicked while `BreakService.instance.breakShown`.
  - `home during break keeps overlay`.
  - `overlay gone by 35 s`.
- [ ] **Step 3:** Implement. Run the tests on the local emulator: `emulator -avd <api34> -no-window &`, then `./gradlew :app:connectedDebugAndroidTest` → pass. If there is no AVD, create one with `avdmanager` from the installed system image.

### Task 4: Screen, CI, release

- `MainActivity`:
  - a single `LinearLayout` in a `ScrollView`, platform widgets only;
  - the copy from Global Constraints;
  - it refreshes once a second while resumed;
  - the pause buttons are enabled only when `canPause`;
  - the switch is disabled unless the phase is WORK, and also disabled while a hold is active.
- `release.yml` `android` job:
  - JDK 17;
  - decodes the `ANDROID_KEYSTORE_B64` secret;
  - runs `./gradlew :app:assembleRelease -PversionName=X.Y.Z -PversionCode=…` with R8 and resource shrinking;
  - uploads `blackbreak-android-vX.Y.Z.apk`;
  - is added to `publish.needs`.
- The `ci.yml` `android` job runs `:core:test :app:testDebugUnitTest :app:assembleDebug` and fails if the APK is 1 MB or larger. Emulator tests run in CI only on `main` pushes (`reactivecircus/android-emulator-runner`, API 34).
